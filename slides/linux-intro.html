Don't read the table. Pick three rows: - Cost: no license keys, no CALs. You can run 1,000 Linux servers for free. - Interface: the command line is the normal way, not the fallback. Server Core is the closest Windows comparison. - Updates: one command updates everything, not just Microsoft's software.

These are the gotchas that trip beginners in week 1: case sensitivity, forward slashes, no Recycle Bin. Point out that every row is on the Windows → Linux Cheat Sheet in the handouts folder.

Samba is a nice bridge: a Linux server can serve shares to Windows PCs, and Windows can't tell the difference. They'll do this in Lab 6.

Transition: the differences on the last slides aren't random. They come from two very different family trees.

Unix was multi-user from day one: users, groups, and file permissions (owner/group/others, rwx) date from this era. That's exactly what Labs 4 and 5 cover, and why Linux permissions look so different from NTFS. Fun fact: Ritchie also created the C language, partly to write Unix.

The kernel is the core that talks to the hardware. GNU supplied almost everything else. In 1992 Linus put Linux under the GNU General Public License (GPL): anyone can use and change it, but if you share your changes you must share the source too. That rule is why Linux stayed open. Linus also wrote Git in 2005 to manage the kernel's code.

This explains a lot: - Drive letters and backslashes come from DOS. - Case-insensitive file names come from DOS. - GUI-first administration comes from the desktop heritage. - Linux's command-line-first, text-file culture comes from Unix terminals.

Linux is about 35 years old; its Unix roots are over 55 years old. Ubuntu's name comes from a Southern African philosophy, often translated "humanity towards others."

The point for students: this isn't a Windows-vs-Linux contest. A typical shop has Active Directory and Windows file servers next to Linux web servers, databases and containers. WSL: they can run Ubuntu on a Windows laptop to practice outside the lab.

Ask the class: "How many of you have a Linux computer in your pocket?" (Anyone with an Android phone.)

Distros differ mostly in the package manager and defaults. What you learn on Ubuntu works on Debian almost unchanged, and most of it works on Red Hat (dnf instead of apt, a few file locations differ).
